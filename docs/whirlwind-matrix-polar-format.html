WhirlwindMatrixPolar

A compact binary container for boat-speed matrices and conditional speed distributions, indexed by wind and optional wave conditions.

.wmpolarLittle-endian44-byte header16-bit payload valuesLZ4 block

This reference describes the v1 binary layout implemented by PolarExplorer v0.3.13. The writer layout is unchanged from v0.3.12; this release adds configurable exports and corrects the reader. It covers all three independent modes: one SOG value per condition, sampled PDF densities, and a Gaussian mean/standard-deviation pair. A file can contain any nonempty combination.

Draft status: updated for configurable wave and PDF export.

The reader now uses the writer's axis order and SOG/sample step-size scales. Section 07 records the legacy v0.3.12 reader defects and the current application export profile. The version remains 1. The source links are pinned to the v0.3.13 release tag, including the reader corrections and new export controls.

Offsets are zero-based. Ranges written [start, end) exclude the end byte. “Body offset” always means an offset in the decompressed payload; it is not a seek position in the compressed file. The format specifies bytes on disk, not the layout of Rust structs in RAM.

The compression is LZ4 block encoding, not the LZ4 frame format. There is no frame magic, checksum, per-mode compression header, per-cell offset table, string metadata, or file name inside the file. The axes and fixed header are uncompressed. The wrapper stores the decoded byte count; compressed length comes from EOF.

Inside the LZ4 block 
sequence = token | literal-length extension? | literals
                 | match offset u16 LE | match-length extension?
token bits:       [7 6 5 4] [3 2 1 0]
                   literals   match − 4

Each sequence starts with a one-byte token. Its high nibble gives the literal count; its low nibble gives match length minus four. For either nibble equal to 15, add extension bytes until a byte below 255 appears (including a zero terminator). Literal extensions precede literals; match extensions follow the two-byte match offset.

The offset is a backward distance, 1–65,535, into already decoded bytes. Copy sequentially so overlapping matches can repeat newly written bytes. The final sequence contains only literals and no offset. At least the last five decoded bytes are literals, except bodies shorter than five bytes, which are entirely literal. The last match starts at least twelve decoded bytes before the end. See the official LZ4 block specification.

Flags are additive

1 · SOG2 · sampled3 · SOG + sampled4 · Gaussian5 · SOG + Gaussian6 · sampled + Gaussian7 · all three

Flag value 0 and any bit outside 0x0007 are rejected for v1. Flags do not choose a “preferred” mode and do not require the three representations to agree.

02 / AXES & INDEXING

Axis order and value order are different

The axis metadata starts with wind. The payload is arranged as a sequence of wave-conditioned wind matrices, so wave coordinates are the outer indices. Within each matrix, TWS changes fastest.

AxisFirst file byteLengthUnit / permitted values
TWA444TDegrees, 0–360 inclusive; T > 0.
TWS44 + 4T4WKnots, 0–70 inclusive; W > 0.
Wave height44 + 4(T+W)4HMetres, 0–100 inclusive.
Wave angle44 + 4(T+W+H)4DDegrees, 0–360 inclusive.
Wave period44 + 4(T+W+H+D)4PSeconds, 0–1000 inclusive.
SOG sample positions44 + 4(T+W+H+D+P)4BKnots, 0–60 inclusive; B > 0 when sampled PDF is present.

All axes contain finite, strictly increasing float32 values. Spacing can be irregular. A count of 1 is valid; uniform increments are not implied. SOG sample positions are the coordinates at which densities are stored; no separate array of bin edges is encoded. Likewise, visual cell boundaries and interpolation rules are not stored.

Wave-independent polar

H = D = P = 0. The three axis arrays consume zero bytes. There is one wind matrix, not zero matrices.

H′ = D′ = P′ = 1
C = T × W

Wave-conditioned polar

H, D, P > 0. All combinations exist logically; absent speeds use sentinels. One or two populated wave axes with the others empty is invalid.

H′ = H; D′ = D; P′ = P
C = H × D × P × T × W

H′ = max(H,1), D′ = max(D,1), and P′ = max(P,1). For zero-based indices h,d,p,t,w, define:

waveIndex = (h × D′ + d) × P′ + p
k = (waveIndex × T + t) × W + w
  = ((((h × D′ + d) × P′ + p) × T + t) × W + w)
C = H′ × D′ × P′ × T × W
height h · slowest→ wave angle d→ period p→ TWA t→ TWS w · fastest cell index→ SOG sample b · sampled mode only
Angle semantics need an external agreement.

The file stores a numeric wave angle in degrees but contains no field identifying its reference frame (absolute direction, bow-relative angle, or wind-relative angle). It also stores no tack-symmetry flag. Consumers must agree on the angle convention; a 0–180° TWA axis alone is not an encoded instruction to mirror it to 360°.

03 / MODE PAYLOADS

Three independent, contiguous blocks

Let S, F and G be 1 when SOG, sampled PDF and Gaussian PDF are present, or 0 otherwise. Every scalar in the decompressed body is a little-endian u16. Modes are grouped into whole arrays; representations of the same cell are not interleaved across modes.

SOG base      = 0                     length = 2 × C × S
Sampled base  = 2 × C × S             length = 2 × C × B × F
Gaussian base = 2 × C × S + 2 × C × B × F
                                      length = 4 × C × G
L = 2 × C × (S + B × F + 2 × G)

Absent modes consume no bytes. There are no per-cell tags. Gaussian parameters are interleaved within that mode: μ₀, σ₀, μ₁, σ₁, …

0x0001 · SOG

A scalar speed

One quantized speed for each wind/wave condition. Input values must be finite, 0–60 knots inclusive, or missing.

byte = 2 × k
q = u16le(body, byte)

0xFFFF (65,535) means missing. 0 is a valid zero speed. Valid numeric codes span 0–65,534.

0x0002 · SAMPLED PDF

A density array

B density samples for each condition, ordered by increasing SOG sample position. Densities are finite, nonnegative values with nominal units of 1/knot.

byte = sampledBase
     + 2 × (k × B + b)

0xFFFF is invalid. An all-zero curve is allowed by the codec. It has no probability mass; no missing-curve flag is provided.

0x0004 · GAUSSIAN PDF

Two parameters

Mean μ and standard deviation σ, each quantized over 0–60 knots. There is no stored amplitude, variance, mixture weight, or density array.

byteμ = gaussianBase + 4k
byteσ = byteμ + 2

FF FF FF FF means missing. A sentinel in only one parameter is invalid. σ = 0 represents a point mass at μ.

SOG and sampled PDF: the writer’s quantization

Both modes use the same algorithm with a separate global scale per mode. Let M be the maximum present value over the entire mode, across all wave and wind cells (and all density samples for sampled PDF). The input arrays are float32; the maximum and division are computed in float64 before the scale is cast to float32.

Q = 65534
s = 1                                  if M = 0 (including absent / all-missing)
s = float32(M / Q)                     otherwise
s = float32(M)                         if that conversion underflows to 0

q = clamp(round(value / float64(s)), 0, Q)
q = 0                                  for value = 0
q = 65535                              for missing SOG only

reconstruction: value ≈ q × s

The writer uses nearest rounding, with half-way cases rounded away from zero (all accepted values are nonnegative). Typical quantization error is at most half a step, apart from floating-point rounding and saturation. The scale is a step size in the emitted file. The current reader uses q × s. The v0.3.12 reader and specification used an extra division; see the compatibility note.

Gaussian: fixed-range parameters

qμ = clamp(round(float64(μ) / 60 × 65534), 0, 65534)
qσ = clamp(round(float64(σ) / 60 × 65534), 0, 65534)
μ ≈ qμ × 60 / 65534
σ ≈ qσ × 60 / 65534

f(v | μ, σ) = exp(−0.5 × ((v − μ) / σ)²) / (σ × √(2π))  for σ > 0

The parameter step is 60/65,534 ≈ 0.000915555 knots, with a maximum rounding error of about 0.000457778 knots. The header’s two scales do not control v1 Gaussian parameters. Quantization can round a very small positive σ to zero.

The normal density integrates to one over the full real line. The 0–60 limit is a parameter encoding range; the file does not encode truncation limits, normalization on a restricted speed domain, display opacity, or the number of standard deviations to draw. A renderer may clip the visible domain, but that is a display decision.

Density samples are not probabilities

A stored sampled value is a density ordinate at a speed coordinate, not a probability for a bin. Probability over an interval requires an integration rule. The codec does not require a sampled curve to integrate to one, specify interpolation, or store bin widths. Irregularly spaced SOG coordinates must be respected. The visualization below uses linear interpolation for its synthetic sampled curves and the analytic normal for its Gaussian curves.

06 / IMPLEMENTATION REFERENCE

Read the envelope before allocating

The following procedure describes the current reader, matching the v1 writer’s axis order and step-size scales.

  1. Bound the file size and require at least 48 bytes for a header plus decompressed-size prefix. Check the eight-byte magic, version, and nonempty known mode flags.
  2. Read the six u32 counts at offsets 12–35 and the two f32 scales at 36–43. Use checked arithmetic for every sum/product. Require finite, nonnegative scales; writer-produced scales are positive.
  3. Require nonempty TWA/TWS, either three empty or three nonempty wave axes, and a nonempty SOG coordinate axis exactly when sampled mode is present.
  4. Compute E, then read the six f32 axes in TWA, TWS, height, wave angle, period, SOG sample order. Check ranges, finiteness, and strict ordering.
  5. Compute C and the expected L = 2C(S + BF + 2G). Read the u32 at E and require equality before decompression.
  6. Decode the LZ4 block starting at E+4 into exactly L bytes, enforcing the output limit. Reject malformed or mismatched output.
  7. Read mode arrays in SOG → sampled → Gaussian order. SOG/sample numbers reconstruct with q × stored_step for this writer profile. Gaussian parameters reconstruct with q × 60 / 65534. Process sentinels before numerical conversion.
  8. Validate reconstructed values and array shapes. A format consumer chooses separately how to interpolate axes, integrate sampled densities, handle missing cells, and display normal tails.

Current codec limits and validation

RuleLimit / behavior
File byte cap64 × 1024 × 1024 = 67,108,864 bytes.

Unknown dataUnknown versions and mode bits are rejected. There is no extensible chunk directory for skipping an unknown mode.

IntegrityNo file checksum. Malformed LZ4 and structural/value validation can detect some corruption, but cannot authenticate the data.

Probability constraintsSampled densities need not integrate to one; Gaussian σ may be zero. No sample count or fitting confidence is stored.

RAM size is not file size. The Rust model reconstructs axes/densities as float32 vectors and optional speeds/Gaussians as Option values. Their allocations, capacity, and option representation are separate from the compact u16 body. The current codec also holds compressed and decompressed buffers during processing; it is not a zero-copy or random-access container.

07 / COMPATIBILITY & EXPORT PROFILE

Application behavior and legacy readers

1. Corrected axis assignment and scalar scaling

The v0.3.12 reader assigned the first five axis arrays to height, wave angle, period, TWA, TWS even though the writer emitted TWA, TWS, height, wave angle, period. This made ordinary wave-independent files fail and could misinterpret wave-conditioned files. The current reader assigns every axis in the writer's order.

ComponentSOG / sampled-PDF formula
Writer (unchanged)s = float32(maximum / 65534); q = round(value / s).
Current reader and specificationvalue ≈ q × s.
Legacy v0.3.12 reader and specificationvalue = q × s / 65534.

The extra division in the legacy reader reduced SOG and sampled densities by approximately 65,534. The writer's step-size convention is authoritative; no version or writer-byte change is needed to correct the reader. Gaussian mode uses its separate fixed-range formula. A third-party file that used the old written specification's full-range scale cannot be distinguished by a header flag and is not automatically migrated.

2. Read-only support for the brief v2 transition

The writer emits v1 with three independent bits. The reader also accepts version 2 with a different interpretation:

  • Only bits 0x0001 (SOG) and 0x0002 are known. In v2, bit 1 means Gaussian parameters, not sampled densities. Bit 0x0004 is invalid.
  • There is no sampled-PDF payload. With the Gaussian bit set, B must be zero and the header's PDF scale must satisfy 0 < sF ≤ 60.
  • Each Gaussian parameter decodes as q × sF / 65534, using the header scale instead of v1's fixed 60. Missing-pair rules and four-byte records are the same.
  • This branch shares the corrected axis assignment and SOG step-size decoding. These formulas describe the accepted branch; they do not establish compatibility with every historic producer.

3. Configurable export profile

Both Export the polar and Export all tabs offer SOG, Histogram (sampled PDF), and Gaussian PDF independently. Any nonempty combination is valid. The UI and API defaults enable all three modes and 4 × 4 × 2 wave buckets (32 combinations). Pass waves:null to the API or disable Split by wave conditions in the UI to omit wave axes.

Wave axisDefault membershipStored coordinates
Height (m)[0,1), [1,3), [3,5), [5,∞)0.5, 2, 4, 6
Direction (°)[−45,45), [45,135), [135,225), [225,315), cyclic0, 90, 180, 270
Period (s)[0,5], (5,∞)2.5, 7.5
  • Customize wave buckets (optional) exposes height/period cutoffs and direction boundaries. Height/period may have 0–63 positive, increasing cutoffs, below 100 m / 1000 s respectively; zero cutoffs mean one all-values bucket. The last bucket has no upper limit. A height equal to a cutoff enters the next bucket; a period equal to a cutoff stays in the preceding bucket. Direction has 2–65 increasing boundaries spanning exactly 360°, with the first in [−360,360). Sectors include their starting boundary and exclude their ending boundary.
  • Wave direction is (wave_from − heading) mod 360, clockwise from the bow, using corrected heading when enabled. The bow sector wraps through 0°, and port/starboard wave directions remain distinct even with symmetric wind polars. Older exports used unsigned 0–180° angles. The container stores no reference-frame flag.
  • Finite bins store midpoint coordinates. An open tail stores its lower cutoff plus half the preceding bin width, capped at the binary axis limit; a sole all-values bucket stores 0. Angular midpoints are normalized to [0,360) and sorted, with payload cells reordered to match. Coordinates must remain distinct in float32. The unchanged v1 layout stores coordinates, not custom cutoff arrays or open-tail bounds. Exact custom membership cannot in general be recovered from coordinates alone.
  • Wave combinations are limited to 4096; the payload is additionally limited to 16,000,000 scalar u16 values. Every combination is recomputed independently, applying visibility, exclusions, source/global/wave filters, priority groups, source weights, confidence, track and polar statistics, interpolation, smoothing and corrections. No interpolation fills across wave combinations. Track samples missing required wave data or heading are omitted. Ordinary 2D polars contribute the same baseline to every combination. Imported wave matrices contribute their SOG coordinates within the selected bucket.
ModeWhat the exporter computes for each wind/wave cell
SOGThe blended scalar, with any custom wind-grid resampling. Missing cells use the SOG sentinel; head-to-wind rows are defined as zero.
Histogram / sampled PDF2–512 equal-width speed bins over 0–60 kn, stored at their centers. Track speed residuals are centered on the selected track statistic plus source edits and weighted by the source's effective blend contribution. Polar values enter as point masses. The per-bin probability fields use wind interpolation/smoothing and optional resampling. Blend corrections translate the distribution; shifted tails clamp into the endpoint bins. A nonempty curve is normalized and divided by bin width to store density in 1/kn. All-zero curves represent no data. This is an empirical histogram, not samples of the Gaussian fit.
Gaussian PDFThe same weighted first/second-moment fit used by the PDF views, preserving within-track variability and between-source disagreement. Standard deviation is at least 0.5 kn. A custom wind grid resamples mean and second moment, then recovers variance. Missing fits use the paired sentinel. The stored parameters describe the full normal; view percentiles may normalize a truncation to 0–60 kn.

The export preview shows the wave-independent wind grid; the chosen wave conditions are recomputed when exporting. Export never changes the original project. The interactive examples in this document use synthetic distributions to demonstrate indexing and bytes; they are not a dataset exported from the app.

4. Application import policy

The binary codec can read PDF-only files, but the editor requires SOG mode. Its import path discards both sampled and Gaussian PDF data and clears the speed-bin axis. It retains wave-conditioned SOG data; the ordinary 2D polar projection averages available wave values at each wind coordinate.
